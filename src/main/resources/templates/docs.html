Getting started

Nord Dev is a Java 21 and Spring Boot platform. Copy the repository, set a secure admin bootstrap password and launch with Maven.

export NORD_ADMIN_EMAIL="admin@example.com"
export NORD_ADMIN_PASSWORD="use-a-unique-password-with-14-chars"
mvn spring-boot:run

The H2 database is stored locally in ./data by default. Set NORD_DB_URL, NORD_DB_USER and NORD_DB_PASSWORD for a production database.

Global Nord ID

Users create one account at /register, then use the same sign-in session for their services, licenses and workspaces. Passwords use BCrypt. The first admin account is bootstrapped using environment variables; the password must be at least 14 characters.

For public deployment, configure HTTPS, a managed SQL database, backups, email verification, password recovery, rate limiting and an external secrets manager.

License verification API

Use the server-side endpoint to verify a key and bind it to an installation identifier. Never ship the private license key in a client-side NUI.

POST /api/licenses/verify
Content-Type: application/json

{"key":"NORD-…","product":"Nord Inventory","serverId":"your-stable-install-id"}

The response is {"valid":true,"product":"…","status":"ACTIVE"}. First verification consumes one activation slot; repeat verification from the same server ID is idempotent. Keys are shown only once and stored as SHA-256 hashes.

Managed update feed

Publish a release from Admin → Updates. Services can check the latest published version per channel:

GET /api/updates/stable
GET /api/updates/beta

The feed returns version, title, notes, channel and publish timestamp. This first release supplies metadata only; signed artifact hosting, staged rollout and client-side updater execution are not wired yet.

Service models

Nord Dev generates ZIP scaffolds for Java CLI, HTTP service, background worker, Discord bot, FiveM resource and NUI interface. Generated code is a starter structure that each service team extends.
